**Форк SonnerStudio агента [Hermes Agent](https://hermes-agent.nousresearch.com/) від Nous Research** — самовдосконалюваний ШІ-агент, розширений голосовим **Hermes Секретар** та візуальним **Composer-Control-HUD** для оркестрації суб-агентів.

Цей форк додає:

- **Composer Control Buttons** — чотири перемикачі в настільному композиторі з кольорами стану в реальному часі (червоний = неактивний, жовтий = підготовка, зелений = активний) :
  1. **Активувати суб-агентів** — активує спеціалізованих суб-агентів ШІ, які самостійно беруть підзавдання, кожен зі своїми спеціалізованими навичками, і постійно вчаться з завдань і з плином часу. Коли Секретар **вимкнено**, команда працює автономно: сама забирає завдання в Hermes Agent (нижчий поріг паралельності, подвійний власний бюджет) і звітує безпосередньо перед ним.
  2. **Секретар** — менеджер агентів: планує і розподіляє завдання, і як комунікатор надає голосовий режим (голосове введення/виведення) з аудіо кінематографічної якості (Kokoro `df_eva`, швидкість 0.9). Він водночас є **комунікаційним інтерфейсом** між мультиагентною системою та людиною-користувачем. Коли його вмикають, він автоматично озброює свою команду (Кнопка 1); коли вимикають знову, зберігається **вручну** активована команда.
  3. **Тимчасове клонування** — дозволяє агентам тимчасово розмножуватися на час виконання завдання, щоб обробляти подібні завдання одночасно.
  4. **Гармонізація та оркестрація** — гармонізує/синхронізує або агентів у межах завдань (без Секретаря), або, коли Секретар активний, агенти керуються ним і гармонізуються/синхронізуються разом з ним.
- **Orchestration HUD** — чотири панелі живого виводу з синьою рамкою під полем введення composer: *Команда суб-агентів*, *Hermes Секретар (аудіокомунікація)*, *Клоновані агенти* та *Гармонізація та навантаження агентів*. Панелі з'являються лише під час виконання реального завдання — без демо-заповнювачів.
- **Hermes Секретар** — голосовий шар, що дозволяє розмовляти з агентом. Німецький TTS через **Kokoro** (`df_eva`, жіночий, швидкість filmreif 0.9), STT через Whisper та фоновий монітор рівня мікрофона (без видимого вікна терміналу). Агент може делегувати суб-агентів для виконання усних запитів.
- **Навчальна команда (живі оцінки)** — смужка під композером показує прогрес навчання: верхній рядок *Hermes Agent*, *Планувальник* і *Секретар*, нижче спеціалісти (Дослідження, Код, Аналіз, Зображення, Аудіо, Планування) у **щонайбільше двох компактних рядках** — ніколи один рядок на спеціаліста. Кожен спеціаліст веде власний рахунок, власну кількість рішень і власний тренд. Відображаються виключно реальні значення; без реальної делегації смужка залишається порожньою.
- **Вибір моделі** — спадне меню групує моделі Nous, **OpenRouter** та категорію **MLX-Runtime nativ** із моделями MLX, доступними локально на дисках системи. Перемикання миттєве та безпечне: завжди працює лише один бекенд (захист RAM на 16 ГБ Mac mini), а при швидкому перемиканні завжди перемагає **останній** вибраний пункт; застарілі завантаження чисто перериваються.
- **MLX Runtime Proxy** — локальний «ледачий» проксі (`:1240`), що обслуговує Kokoro TTS, Whisper STT та MLX-моделі чату по одній за раз, щоб Mac mini з 16 ГБ залишався в межах RAM.

> **Примітка:** MLX-виконавче середовище, німецький Kokoro TTS та голосовий конвеєр Hermes Секретар налаштовані для Apple Silicon (macOS). Див. `plugins/hermes-sekretaerin/` для налаштування.

## Швидке встановлення

### Linux, macOS, WSL2, Termux

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

### Windows (native, PowerShell)

> **Увага:** Нативний Windows запускає Hermes без WSL — CLI, gateway, TUI та інструменти працюють нативно. Якщо віддаєте перевагу WSL2, наведена вище однорядкова команда для Linux/macOS також працює там. Знайшли помилку? Будь ласка, [повідомте про проблеми](https://github.com/NousResearch/hermes-agent/issues).

Виконайте це у PowerShell:

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

Інсталятор робить усе: uv, Python 3.11, Node.js, ripgrep, ffmpeg, **та портативний Git Bash** (MinGit, розпаковується до `%LOCALAPPDATA%\hermes\git` — без прав адміністратора, повністю ізольовано від будь-якої системної інсталяції Git). Hermes використовує цей вбудований Git Bash для запуску команд оболонки.

Якщо у вас уже встановлено Git, інсталятор виявляє його та використовує замість нього. Інакше потрібне лише ~45 МБ завантаження MinGit — він не зачепить і не завадить жодному системному Git.

> **Android / Termux:** Перевірений ручний шлях задокументовано в [посібнику Termux](https://hermes-agent.nousresearch.com/docs/getting-started/termux). У Termux Hermes встановлює відібране додаткове `.[termux]`, оскільки повне додаткове `.[all]` наразі підтягує голосові залежності, несумісні з Android.
>
> **Windows:** Нативний Windows повністю підтримується — наведена вище однорядкова команда PowerShell встановлює все. Якщо віддаєте перевагу WSL2, команда Linux також працює там. Нативна інсталяція Windows живе в `%LOCALAPPDATA%\hermes`; WSL2 встановлюється в `~/.hermes`, як і на Linux.

## Налаштування Hermes Секретар (розширення SonnerStudio)

Голосовий шар розташовано в `plugins/hermes-sekretaerin/`:

```bash
bash plugins/hermes-sekretaerin/setup.sh
```

Це встановлює:
- `mlx-proxy.py` як launchd-демон (обслуговує TTS/STT/MLX-моделі на `:1240`)
- `mic-level.py` як фоновий LaunchAgent (монітор рівня мікрофона, без вікна терміналу)
- `kokoro-tts-server.py` (німецький Kokoro TTS, `df_eva`)

**Збірка Kokoro (одноразово):** див. `plugins/hermes-sekretaerin/BUILD_kokoro.md`. Потрібні заголовки `cmake`, `espeak-ng` та субмодулі `ggml`/`highway`.

**Дозвіл на мікрофон:** надайте macOS *Системні налаштування → Конфіденційність та безпека → Мікрофон* доступ помічнику один раз.

---

Після встановлення:

```bash
source ~/.bashrc    # перезавантажити оболонку (або: source ~/.zshrc)
hermes              # почати спілкування!
```

### Усунення несправностей

#### Windows Defender або антивірус позначає `uv.exe` як шкідливий

Якщо ваш антивірус (Bitdefender, Windows Defender тощо) поміщає `uv.exe` з папки `bin` Hermes (`%LOCALAPPDATA%\hermes\bin\uv.exe`) у карантин, це **хибне спрацювання**. Файл — це `uv` від Astral — Rust-менеджер Python-пакетів, який Hermes постачає для керування своїм Python-середовищем. Антивірусні рушії на основі ML часто позначають непідписані Rust-бінарні файли, що завантажують і встановлюють пакети.

**Щоб перевірити автентичність вашої копії:**

```powershell
# Встановіть GitHub CLI, якщо потрібно
winget install --id GitHub.cli

# Увійдіть у GitHub
gh auth login

# Запустіть перевірку
$uv = "$env:LOCALAPPDATA\hermes\bin\uv.exe"
$ver = (& $uv --version).Split(' ')[1]
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
$zip = "$env:TEMP\uv.zip"
Invoke-WebRequest "https://github.com/astral-sh/uv/releases/download/$ver/uv-x86_64-pc-windows-msvc.zip" -OutFile $zip -UseBasicParsing
gh attestation verify $zip --repo astral-sh/uv
Expand-Archive $zip "$env:TEMP\uv_x" -Force
(Get-FileHash "$env:TEMP\uv_x\uv.exe").Hash -eq (Get-FileHash $uv).Hash
```

Якщо attestation повідомляє «Verification succeeded», а останній рядок друкує `True`, усе гаразд.

**Щоб додати Hermes до білого списку:**
- **Windows Defender:** Запустіть PowerShell як Admin → `Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\hermes\bin"`
- **Bitdefender:** Додайте виняток у консолі Bitdefender (Protection > Antivirus > Settings > Manage Exceptions)
- Додайте до білого списку **папку**, а не хеш файлу — Hermes оновлює `uv`, і хеш змінюється кожну версію

Для додаткового контексту див. звіти upstream від Astral: [astral-sh/uv#13553](https://github.com/astral-sh/uv/issues/13553), [astral-sh/uv#15011](https://github.com/astral-sh/uv/issues/15011), [astral-sh/uv#10079](https://github.com/astral-sh/uv/issues/10079).

## Початок роботи

```bash
hermes              # Інтерактивний CLI — розпочати розмову

hermes doctor       # Діагностувати будь-які проблеми
```

## Обійти збір API-ключів — Nous Portal

Hermes працює з будь-яким провайдером на ваш вибір — це не зміниться. Але якщо ви не хочете збирати п'ять окремих API-ключів для моделі, веб-пошуку, генерації зображень, TTS та хмарного браузера, **[Nous Portal](https://portal.nousresearch.com)** покриває їх усі в рамках однієї підписки:

- **300+ моделей** — оберіть будь-яку з них за допомогою `/model <name>`
- **Tool Gateway** — веб-пошук (Firecrawl), генерація зображень (FAL), текст-в-мовлення (OpenAI), хмарний браузер (Browser Use) — усе маршрутизується через вашу підписку. Жодних додаткових акаунтів.

Одна команда з чистої інсталяції:

```bash
hermes setup --portal
```

Це виконує вхід через OAuth, встановлює Nous як вашого провайдера та вмикає Tool Gateway. Перевіряйте, що підключено, у будь-який час за допомогою `hermes portal info`. Повні деталі на [сторінці документації Tool Gateway](https://hermes-agent.nousresearch.com/docs/user-guide/features/tool-gateway).

Ви все ще можете підключати власні ключі для кожного інструмента коли завгодно — шлюз працює по кожному бекенду окремо, а не за принципом «все або нічого».

## Коротка довідка: CLI проти обміну повідомленнями

У Hermes два точки входу: запустіть термінальний інтерфейс за допомогою `hermes`, або запустіть gateway і спілкуйтеся з ним з Telegram, Discord, Slack, WhatsApp, Signal або Email. Коли ви в розмові, багато slash-команд спільні для обох інтерфейсів.

## Міграція з OpenClaw

Якщо ви переходите з OpenClaw, Hermes може автоматично імпортувати ваші налаштування, спогади, навички та API-ключі.

**Під час першого налаштування:** Майстер налаштування (`hermes setup`) автоматично виявляє `~/.openclaw` і пропонує міграцію до початку конфігурації.

**Будь-коли після встановлення:**

```bash
hermes claw migrate              # Інтерактивна міграція (повний пресет)
hermes claw migrate --dry-run    # Попередній перегляд того, що буде мігровано
hermes claw migrate --preset user-data   # Міграція без секретів
hermes claw migrate --overwrite  # Перезаписати наявні конфлікти
```

Що імпортується:

- **SOUL.md** — файл персони
- **Спогади (Memories)** — записи MEMORY.md та USER.md
- **Навички (Skills)** — створені користувачем навички → `~/.hermes/skills/openclaw-imports/`
- **Білий список команд** — шаблони підтвердження
- **Налаштування обміну повідомленнями** — конфігурації платформ, дозволені користувачі, робоча директорія
- **API-ключі** — дозволені секрети (Telegram, OpenRouter, OpenAI, Anthropic, ElevenLabs)
- **Ассети TTS** — аудіофайли робочого простору
- **Інструкції робочого простору** — AGENTS.md (з `--workspace-target`)

Див. `hermes claw migrate --help` для всіх опцій або скористайтеся навичкою `openclaw-migration` для інтерактивної міграції з керівництвом агента та попереднім переглядом dry-run.

## Участь у розробці

Ми вітаємо внески! Див. [Посібник з участі](https://hermes-agent.nousresearch.com/docs/developer-guide/contributing) для налаштування розробки, стилю коду та процесу PR.

Швидкий старт для учасників — скористайтеся стандартним інсталятором, потім працюйте з
повним git-чекаутом, який він створює за шляхом `$HERMES_HOME/hermes-agent` (зазвичай
`~/.hermes/hermes-agent`). Це відповідає розташуванню, яке використовують `hermes update`,
керований venv, ледачі залежності, gateway та інструментарій документації.

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
cd "${HERMES_HOME:-$HOME/.hermes}/hermes-agent"
uv pip install -e ".[all,dev]"
scripts/run_tests.sh
```

Ручний запасний варіант клонування (для тимчасових клонів/CI, де ви навмисно не
хочете керованого розташування інсталяції):

Створіть venv поза деревом клонованого коду — venv усередині директорії,
з якої працює агент, може бути витертий відносним шляхом команди, яку агент
запускає проти свого власного чекауту, знищуючи працююче середовище виконання посеред сесії.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv ~/.hermes/venvs/hermes-dev --python 3.11
source ~/.hermes/venvs/hermes-dev/bin/activate
uv pip install -e ".[all,dev]"
scripts/run_tests.sh
```
